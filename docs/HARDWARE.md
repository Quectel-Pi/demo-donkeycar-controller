# 硬件与协议参考

本文记录实测确认的接线、寄存器与报文格式，用于二次开发或移植到同类扩展板。

---

## 1. 扩展板

- 型号：树莓派 4B 扩展板 **A 款（DC 接口）**
- 板载 MCU：`STC8H1K08`（TSSOP20），I2C 从机，不跑固件升级
- 电机驱动：4 × `YX-4055AM`（H 桥）
- I2C 从机地址：**0x7A**

### STC8H1K08 引脚

| 脚 | 引脚 | 网络 | 脚 | 引脚 | 网络 |
|---|---|---|---|---|---|
| 1 | P1.2 | MOTOR3_F | 11 | P3.0 | SERVO6_RXD |
| 2 | P1.3 | MOTOR3_B | 12 | P3.1 | SERVO5_TXD |
| 3 | P1.4 | MOTOR4_B | 13 | P3.2 | **SCL** |
| 4 | P1.5 | MOTOR4_F | 14 | P3.3 | **SDA** |
| 5 | P1.6 | MOTOR2_B | 15 | P3.4 | ADC_BAT |
| 6 | P1.7 | MOTOR2_F | 16 | P3.5 | SERVO3 |
| 7 | P5.4 | MOTOR1_B | 17 | P3.6 | SERVO2 |
| 8 | VCC | 电源 | 18 | P3.7 | SERVO1 |
| 9 | ADC_VREF+ | 基准 | 19 | P1.0 | SERVO4 |
| 10 | GND | 地 | 20 | P1.1 | MOTOR1_F |

### 40pin 关键网络

| 排针脚 | 网络 | 说明 |
|---|---|---|
| pin 3 | SDA | I2C 数据（本车挂 `/dev/i2c-3`） |
| pin 5 | SCL | I2C 时钟 |
| pin 7 | RX_CON（GPIO4） | 串口方向控制 |
| pin 13 | TX_CON（GPIO27） | 串口方向控制 |
| pin 31 | BUZZER（GPIO6） | 蜂鸣器（经 R13 1K → Q1 8050 基极） |

> `TX_CON` / `RX_CON` 未经 STC8H 中转，是主控 GPIO 直驱；要恢复 40pin 串口（总线舵机）需先拉高这两脚。
> 蜂鸣器不需要独立供电：5V 直供有源蜂鸣器，MCU 只驱动三极管基极。

## 2. I2C 寄存器表

写事务格式：`[寄存器地址][数据...]`；读事务：先写寄存器地址，再读 N 字节。

| 寄存器 | 长度 | 含义 |
|---|---|---|
| 0 | 2 字节小端 | 电池电压，单位 mV（如 `04 1E` = 7684 → 7.68 V） |
| 21 ~ 26 | 1 | PWM 舵机角度 0~180 |
| **31 ~ 34** | 1（int8） | **电机 M1 ~ M4，-100 ~ 100** |
| 40 | 命令块 | 舵机带时间控制 |

电机寄存器 = `31 + (通道号 - 1)`。

> ⚠️ **`i2cdetect` 对本板是假阴性**：STC8H 不响应 SMBus quick probe，扫描结果是全 `--`，
> 但完整读写事务正常。判断板子是否在线请用「读电池电压」，不要用 `i2cdetect`。

## 3. 轮位与符号

| 通道 | 位置 | 符号（`I2C_SIGNS`） |
|---|---|---|
| M1 | 左前 | +1 |
| M2 | 右前 | −1（电机反装） |
| M3 | 左后 | +1 |
| M4 | 右后 | −1（电机反装） |

驱动层约定「正数 = 该轮向前」，反装差异全部由符号吸收，接线不必对调。

麦轮运动学（`src/turbopi/chassis.py`）：

```
M1 = +vx -vy -wz        (左前)
M2 = +vx +vy +wz        (右前)
M3 = +vx +vy -wz        (左后)
M4 = +vx -vy +wz        (右后)
```

因此：`vx>0` 直行；`vy>0` 右平移；`wz>0` 左转（左侧倒车、右侧前进）。

### 启动扭矩

实测：占空比 **15% 只"嗡嗡"响不转，约 35% 才能起步**。这是直流减速电机的静摩擦特性，
不是驱动问题；调速时把普通档上限设在 30% 以上才有明显动作。

## 4. 手柄报文（XInput over USB）

本车机内核未编译 joystick 支持（`CONFIG_INPUT_JOYSTICK=n`，没有 xpad/joydev，
`/dev/input/js*` 永远不存在），因此手柄由 `src/turbopi/xinput.py` 通过 **usbfs 直读**
（`USBDEVFS_SUBMITURB` + 中断 IN 端点），约 800 Hz。

报文体 20 字节，关键字节：

| 偏移 | 内容 |
|---|---|
| 0 | `0x00` |
| 1 | `0x14`（或 `0x01`） |
| 2 | 十字键 + START/BACK + L3/R3 |
| 3 | LB/RB + 面键 + GUIDE |
| 4 / 5 | LT / RT（0~255） |
| 6~7 | LX（int16，小端） |
| 8~9 | LY |
| 10~11 | RX |
| 12~13 | RY |

### 两套面键布局

| 位（`data[3]`） | `standard`（Xbox 等） | `flydigi`（APEX5 实测） |
|---|---|---|
| `0x01` / `0x02` | LB / RB | LB / RB |
| `0x04` / `0x08` | A / B | — |
| `0x10` / `0x20` | X / Y | A / B |
| `0x40` | GUIDE | X |
| `0x80` | — | Y |

> APEX5 的面键整体比标准布局高 2 位，Y 落在 `0x80`。
> `xinput.py` 按 `VID:PID`（`37d7:2501`）自动选 `flydigi`，其他手柄回落 `standard`；
> 也可用 `TURBOPI_PAD_LAYOUT=standard|flydigi` 强制指定。

低字节（`data[2]`）两套布局一致：十字键 `0x01/0x02/0x04/0x08`、START `0x10`、BACK `0x20`、
L3 `0x40`、R3 `0x80`。

## 5. 另一代扩展板（AA55 串口）

`src/turbopi/protocol.py` / `board.py` / `serialport.py` 保留了另一代扩展板的串口协议：
13 字节帧 `AA 55 <func> <len> <data...> <crc8>`，1000000 8N1。**本车（4B A 款）不用这条路**，
电机走 I2C。保留是为了兼容与参考；如需切换，把 `TURBOPI_BACKEND` 设为 `serial` 或 `auto`。
